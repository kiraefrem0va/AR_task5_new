# Расширение сцены на Three.js: управление объектом, освещение, UI

Учебный WebAR-проект на **Three.js 0.160.0 + WebXR**. Пользователь находит пол, видит на нём кольцо-маркер и тапом ставит 3D-объект. Панель внизу экрана позволяет выбрать модель, цвет и материал, повернуть объект и удалить последний поставленный. Освещение строится по HDRI-карте `room.hdr`.

Без сборщиков и npm: чистый HTML и JavaScript ES-модули. Three.js подключается через `importmap` с CDN jsDelivr.

---

## 1. Структура проекта

Все файлы лежат в одной папке, без подпапок, чтобы их можно было загрузить на GitHub Pages через веб-интерфейс.

| Файл | Что внутри |
|---|---|
| `index.html` | Разметка страницы, `importmap` для Three.js, корень DOM Overlay (`#overlay`) с подсказкой, плашкой ошибок и панелью |
| `style.css` | Оформление: тёмная полупрозрачная карточка, кнопки, круглые образцы цвета, адаптация под телефон |
| `main.js` | Класс **App**, точка входа. Создаёт рендерер, сцену и камеру и связывает все модули между собой |
| `models.js` | Класс **ModelFactory**: создание моделей из геометрий Three.js, клонирование, смена цвета и материала |
| `materials.js` | Класс **MaterialLibrary** и списки `COLORS` и `PRESETS`: PBR-материалы, палитра, пресеты поверхности |
| `lighting.js` | Класс **LightingManager**: загрузка HDRI, `scene.environment`, запасной RoomEnvironment |
| `ar.js` | Класс **ARManager**: AR-сессия, hit-test, кольцо-маркер, обработка тапа (`select`) |
| `ui.js` | Класс **UIManager**: построение панели, обработка кнопок, подсказки, сообщения об ошибках |
| `preview.js` | Класс **PreviewScene**: режим предпросмотра без AR (светлый фон и пол) |
| `room.hdr` | HDRI-карта окружения (1K) |

### Как модули связаны между собой

```
main.js (App)
 ├── LightingManager  ← lighting.js   — освещение
 ├── ModelFactory     ← models.js     — модели
 │     └── MaterialLibrary ← materials.js — материалы
 ├── PreviewScene     ← preview.js    — предпросмотр без AR
 ├── ARManager        ← ar.js         — AR-события
 └── UIManager        ← ui.js         — интерфейс
```

Модули не обращаются друг к другу напрямую. Например, `UIManager` ничего не знает о Three.js: по нажатию кнопки он только вызывает обработчик (`onColor`, `onRotate` и т. д.), а что сделать, решает `App`. Так же устроен `ARManager`: он сообщает «был тап в такой точке» (`onSelect`), а объект создаёт `App` с помощью `ModelFactory`.

## 2. Что делает каждый класс

### App (`main.js`)
- Создаёт `WebGLRenderer` (с прозрачностью, `xr.enabled = true`, `setPixelRatio` не больше 2), сцену, камеру и OrbitControls.
- Хранит текущий выбор пользователя: `state = { type, color, preset }`.
- Хранит список поставленных объектов `placed`. Последний элемент списка и есть «последний поставленный».
- Определяет, к какому объекту применять цвет, материал и поворот (геттер `target`): в AR это последний поставленный объект, в предпросмотре — модель предпросмотра.
- Переключает режимы: при запуске AR скрывает предпросмотр, при выходе возвращает его.
- В цикле отрисовки обновляет hit-test (в AR) или OrbitControls (в предпросмотре), плавно поворачивает объекты и проигрывает анимацию их появления.

### ModelFactory (`models.js`)
- Один раз строит 4 модели-прототипа из стандартных геометрий Three.js:

| Модель | Размер | Основная (перекрашиваемая) часть | Нейтральные части |
|---|---|---|---|
| Лампа | ~44 см | абажур (`LatheGeometry`) | металлическое основание, латунная ножка, светящаяся лампочка, латунные ободки |
| Ваза | ~36 см | корпус (`LatheGeometry` по плавной кривой `SplineCurve`) | золотой ободок горлышка |
| Стул | ~58 см | сиденье и спинка (`RoundedBoxGeometry`) | деревянные ножки и стойки |
| Растение | ~35 см | горшок (`LatheGeometry`) | земля, зелёные листья |

- У каждой модели низ находится на `y = 0`, центр по X/Z — в точке `(0, 0)`, поэтому объект встаёт ровно на поверхность в точку кольца.
- Под каждой моделью есть мягкая «контактная тень» (полупрозрачная плоскость с радиальным градиентом), чтобы объект не казался висящим в воздухе.
- `create(type, color, preset)` клонирует прототип. Геометрии и нейтральные материалы у копий общие, а материал основной части у каждой копии свой, поэтому цвет одного объекта не меняет цвет остальных.
- `setColor()` меняет только цвет существующего материала, без пересоздания.
- `setPreset()` создаёт новый материал и освобождает старый (`dispose()`).
- `dispose()` освобождает ресурсы при удалении объекта.

### MaterialLibrary (`materials.js`)
- `COLORS`: палитра из 8 цветов.
- `PRESETS`: 4 пресета поверхности.
- `createMain(preset, color)` создаёт PBR-материал основной части:

| Пресет | Материал | Параметры |
|---|---|---|
| Матовый | `MeshStandardMaterial` | roughness 0.92, metalness 0 — почти нет бликов |
| Глянец | `MeshStandardMaterial` | roughness 0.18, metalness 0 — чёткие блики от HDRI |
| Металл | `MeshStandardMaterial` | roughness 0.22, metalness 1 — отражает окружение, окрашенный металл |
| Стекло/лак | `MeshPhysicalMaterial` | roughness 0.06, clearcoat 1, clearcoatRoughness 0.02, полупрозрачность 0.78 |

- Нейтральные материалы (металл, латунь, дерево, земля, листья, лампочка) создаются один раз и общие для всех объектов.

### LightingManager (`lighting.js`)
- Загружает `room.hdr` через `RGBELoader`.
- Через `PMREMGenerator` подготавливает карту для PBR-отражений и записывает её в `scene.environment`.
- Метод `rebuild()` пересобирает карту окружения: при запуске AR и после восстановления WebGL-контекста (событие `webglcontextrestored`). На время пересборки XR-режим рендерера выключается, иначе карта рисовалась бы через XR-камеру.
- Если файл не загрузился, включает запасной `RoomEnvironment` и показывает сообщение на экране.
- Пишет в консоль, какое освещение включилось:
  - `[Освещение] Включено HDRI-освещение из файла «room.hdr»`
  - или `[Освещение] Включено запасное освещение RoomEnvironment`
- Включает тональную коррекцию ACES Filmic.
- `scene.background` не трогает, чтобы в AR было видно изображение с камеры.

### ARManager (`ar.js`)
- `checkSupport()` проверяет HTTPS, наличие `navigator.xr` и `isSessionSupported('immersive-ar')`.
- `start()` запрашивает сессию `immersive-ar`:
  - `requiredFeatures: ['hit-test']`
  - `optionalFeatures: ['dom-overlay']`, `domOverlay: { root: #overlay }`
  - создаёт `XRHitTestSource` от пространства `viewer` (луч из центра экрана или «взгляда»).
- `update(frame)` вызывается каждый кадр. Через `frame.getHitTestResults()` находит поверхность и ставит туда кольцо-маркер.
- Тап обрабатывается через `session.addEventListener('select', …)`, а не через `getController(0)`. Это событие приходит и от касания экрана телефона, и от любого из двух контроллеров в эмуляторе.
- При тапе передаёт в `App` позицию кольца. Если поверхность ещё не найдена, передаёт `null`, и `App` показывает подсказку.
- `stop()` и событие `end` отменяют hit-test source и возвращают приложение в предпросмотр.

### UIManager (`ui.js`)
- Строит панель из списков моделей, цветов и пресетов.
- Подписанные группы кнопок: **Модель / Цвет / Материал / Поворот**. Выбранный вариант подсвечивается.
- Кнопки только с текстом, без иконок: «Влево 45°», «Вправо 45°», «Сброс», «Удалить последний», «Запустить AR / Выйти из AR», «Свернуть / Развернуть».
- Вешает на панель обработчик `beforexrselect` с `preventDefault()`, чтобы касания панели не ставили объект.
- Показывает короткую подсказку сверху («Предпросмотр», «Наведите на пол», «Коснитесь, чтобы поставить») и ошибки (на экране и в консоли).

### PreviewScene (`preview.js`)
- Пол, плавно растворяющийся к краям, и текущая модель на нём.
- Светлый фон задаётся через `renderer.setClearColor`, а не через `scene.background`. В AR цвет очистки становится прозрачным.

## 3. Как выполнено каждое требование

| Требование | Как сделано |
|---|---|
| **AR-сцена Three.js + WebXR, сессия immersive-ar** | `ar.js → start()`: `navigator.xr.requestSession('immersive-ar', …)`, затем `renderer.xr.setSession(session)` |
| **Hit-test через XRHitTestSource и getHitTestResults** | `session.requestHitTestSource({ space: viewerSpace })`, затем каждый кадр `frame.getHitTestResults(hitTestSource)` (`ar.js → update()`) |
| **Кольцо-маркер на поверхности** | `ar.js → _createReticle()`: белое кольцо и пульсирующее внутреннее кольцо. Его матрица берётся из позы hit-test |
| **По тапу объект ставится в точку кольца и остаётся на месте** | `select`, затем `onARSelect(position)`. Объект добавляется в сцену в мировых координатах и больше не двигается |
| **Каждый тап ставит новый объект** | `factory.create(type, color, preset)` с текущим выбором. Объект добавляется в список `placed` |
| **UI-кнопки управления объектом** | Панель `ui.js`: Модель / Цвет / Материал / Поворот / Удалить последний |
| **Поворот** | Кнопки ±45° и «Сброс». Объект плавно поворачивается к целевому углу (`animate()` в `main.js`) |
| **Смена цвета** | 8 круглых образцов. Перекрашивается основная часть модели (абажур, корпус вазы, сиденье и спинка, горшок) |
| **Смена модели** | 4 модели. В предпросмотре модель меняется сразу, в AR следующий тап ставит выбранную модель |
| **Цвет, материал и поворот применяются к последнему объекту** | Геттер `target` в `main.js` возвращает последний элемент `placed` |
| **Удалить последний** | `deleteLast()`: убирает объект из сцены и освобождает его материал |
| **Освещение через HDRI / scene.environment** | `lighting.js`: `RGBELoader`, `PMREMGenerator`, `scene.environment`. Запасной вариант — `RoomEnvironment`. Какое освещение включилось, пишется в консоль |
| **PBR-материалы с roughness и metalness** | `MeshStandardMaterial` и `MeshPhysicalMaterial` (clearcoat) в `materials.js`. 4 пресета |
| **Структура разделена на модули и классы** | Загрузка и создание моделей — `models.js` + `materials.js`; AR-события — `ar.js`; UI — `ui.js`; освещение — `lighting.js`; связка — `main.js` |
| **UI работает в AR и не мешает взаимодействию** | DOM Overlay (`dom-overlay`, `domOverlay.root = #overlay`). На панели `beforexrselect` + `preventDefault`. Пустые места оверлея пропускают касания (`pointer-events: none`). Панель можно свернуть кнопкой «Свернуть» |
| **Оверлей поверх эмулятора** | У `#overlay` `z-index: 2147483647` |
| **Модели без файлов, low-poly, 20–60 см** | Все модели собраны в `models.js` из `Cylinder`, `Lathe`, `Sphere`, `Torus`, `RoundedBox`, `Circle`. Размеры в метрах |
| **Предпросмотр без AR** | `preview.js` + OrbitControls: светлый фон, пол, вся панель работает. Если AR не поддерживается, кнопка пишет «AR не поддерживается», а причина выводится в консоль |
| **Производительность** | Прототипы строятся один раз, затем `clone()`. Геометрии и нейтральные материалы общие. `setPixelRatio(min(dpr, 2))`. Временные векторы переиспользуются. Подсказка обновляется только при изменении состояния, а не каждый кадр |
| **Обработка ошибок** | `try/catch` при запуске AR, при постановке объекта, при загрузке HDRI, в обработчиках кнопок и при старте приложения, плюс перехват `unhandledrejection`. Сообщение показывается красной плашкой на экране и пишется в консоль |

## 4. Как запустить

### Локально
WebXR и ES-модули не работают при открытии файла двойным кликом (`file://`), поэтому нужен локальный сервер. В папке проекта выполните:

```bash
python3 -m http.server 8000
```

Затем откройте в Chrome адрес **http://localhost:8000/**. Адрес `localhost` считается безопасным, поэтому WebXR работает и без HTTPS.

### На GitHub Pages
Загрузите все файлы (включая `room.hdr`) в корень репозитория и включите Pages в Settings → Pages. GitHub Pages работает по HTTPS, поэтому AR запустится на телефоне с Android и ARCore в Chrome.

## 5. Как тестировать в Immersive Web Emulator

1. Установите в Chrome расширение **Immersive Web Emulator** (Meta).
2. Откройте страницу (http://localhost:8000/ или адрес GitHub Pages).
3. Откройте DevTools (F12) и найдите вкладку **WebXR**. В ней выберите устройство **Meta Quest 3**.
4. **Перезагрузите страницу.** Эмулятор подключается при загрузке, после этого кнопка вместо «AR не поддерживается» покажет «Запустить AR».
5. Нажмите **«Запустить AR»**. В консоли появятся сообщения `[AR] Сессия запущена…`.
6. В эмуляторе поверните «голову» (гарнитуру) так, чтобы она смотрела на пол виртуальной комнаты. Появится **кольцо-маркер**, а подсказка сверху станет зелёной: «Коснитесь, чтобы поставить».
7. Нажмите кнопку **триггера** у любого контроллера (в панели эмулятора). Это событие `select`, и в точке кольца появится объект.
8. Проверьте панель:
   - выберите другую **Модель**, и следующий тап поставит её;
   - нажмите **Цвет** или **Материал**, и изменится только последний поставленный объект;
   - кнопки **Влево 45° / Вправо 45°** поворачивают последний объект, **Сброс** возвращает исходный угол;
   - **Удалить последний** убирает последний объект;
   - нажатия по панели **не ставят** новый объект: это работает благодаря `beforexrselect`.
9. Нажмите **«Выйти из AR»**, и вы вернётесь в предпросмотр.

**Проверка без эмулятора.** Если открыть страницу без эмулятора, работает режим предпросмотра. Сцену можно вращать мышью (колёсико приближает), а все кнопки модели, цвета, материала и поворота сразу видны на модели. Так удобно сравнивать матовый, глянцевый, металлический и лаковый материалы: разница хорошо заметна по отражениям HDRI.

**Проверка запасного освещения.** Временно переименуйте `room.hdr` и обновите страницу. В консоли появится «Включено запасное освещение RoomEnvironment», а на экране — сообщение о том, что файл не загрузился.

## 6. Полезно знать для защиты

- **Почему `select` у сессии, а не `getController(0)`?** Событие `select` у `XRSession` приходит от любого источника ввода: касания экрана телефона, левого или правого контроллера. `getController(0)` слушает только один контроллер, и в эмуляторе Quest 3 со вторым контроллером тап мог бы «потеряться».
- **Почему `scene.background` не задаётся?** В AR фон должен быть прозрачным, чтобы было видно камеру. Светлый фон предпросмотра задаётся цветом очистки рендерера, который в AR становится прозрачным.
- **Почему объекты могли стать чёрными в AR и как это исправлено?** При входе в AR браузер делает WebGL-контекст XR-совместимым и иногда при этом пересоздаёт его. Карта окружения, подготовленная заранее, пропадает, и объекты остаются без света. Поэтому исходная HDR-текстура хранится в памяти, а `LightingManager.rebuild()` заново готовит карту окружения при запуске AR и после восстановления контекста.
- **Зачем PMREM?** Он заранее «размывает» HDRI под разную шероховатость. Поэтому матовый материал отражает окружение мягко, а глянцевый и металлический — чётко.
- **Почему у каждого объекта свой материал основной части?** Иначе смена цвета последнего объекта перекрасила бы все объекты этого типа. Геометрии при этом общие, так что память не тратится зря.
- **Что происходит с объектами после выхода из AR?** Они удаляются. Новая AR-сессия задаёт новую систему координат, и старые позиции в ней уже не имеют смысла.
